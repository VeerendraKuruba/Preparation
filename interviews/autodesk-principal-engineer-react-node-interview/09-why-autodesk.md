# Why Autodesk? — Prep for Every Round

> Interviewers at Autodesk ask **"Why Autodesk?"** in recruiter screens, HM rounds, and leadership conversations. Have a 30-second, 2-minute, and 5-minute version ready.

---

## 30-Second Version

> "Autodesk builds the software that architects, engineers, and manufacturers use to design the physical world. I'm a **Principal Frontend Engineer** — React, design systems, complex UIs — and the move to cloud web surfaces and APS Viewer experiences is exactly the kind of UI platform work I want to lead."

---

## 2-Minute Version

**Hook — mission:**
> "Most of my career has been building **React UIs** — dashboards, viewer shells, admin consoles, design systems. What draws me to Autodesk is that users aren't clicking generic CRUD — they're designing buildings, products, and infrastructure. The **frontend challenge** is harder and more meaningful: large files, 3D viewer chrome, collaboration, perf at scale."

**Technical fit:**
> "Desktop CAD is moving to **web**. That means React surfaces for project browsers, APS Viewer integration, properties panels, comments, permissions UX. I know how to architect component trees, server state with React Query, code splitting, a11y, and Core Web Vitals on dense UIs. Node BFF patterns for OAuth — I've integrated with — but **my depth is the UI layer**."

**Principal fit:**
> "I want to define **frontend platform patterns** — design system, state strategy, perf budgets — that multiple Autodesk web teams reuse during the cloud transition. That's Principal leverage on the React side."

**Personal:**
> "[Optional: e.g., studied architecture / worked in construction tech / used Fusion in a side project — only if true]"

**Close:**
> "I'm leaving [current company] on good terms — I've delivered [X], and I'm ready for broader platform scope. Autodesk is where I want that next chapter."

---

## 5-Minute Version (If They Probe Deep)

Add these layers:

### 1. Know the company (show research)

| Topic | Talking point |
|-------|---------------|
| **Products** | AutoCAD, Revit, Fusion 360, Maya — desktop leaders moving cloud |
| **APS** | Developer platform — Viewer, Model Derivative, Design Automation |
| **Trend** | Connected data, digital twin, sustainability in AEC (buildings account for ~40% energy use — design software matters) |
| **AI** | AI assistant across products; AI in engineering workflow (align with Round 5) |

### 2. Why not stay at current company?

**Good reasons:**
- Plateau in scope — want platform/org impact
- Industry alignment — passion for design/build domain
- Cloud transition timing — want to be part of it early

**Bad reasons:**
- Compensation only (mention comp after interest)
- Badmouthing manager/team
- "Autodesk is easy" (it's not — process is rigorous)

### 3. Why Principal at Autodesk specifically?

> "Autodesk web teams need Principals who can own **UI architecture** — viewer shells, design systems, state and perf — while partnering with backend on API contracts. I bring deep React/TypeScript plus the communication to align design, PM, and engineering during a multi-year cloud UI transition."

---

## "Why This Role?" (React-Heavy Principal)

> "This role is **frontend-first** — complex React surfaces, APS Viewer integration, design systems, performance. I'll shape how teams build UIs on APS, not own backend microservices. That's exactly where I've been driving impact: component platforms, migration to React, and measurable perf wins."

---

## "Why Leave Your Current Job?"

**Template:**
> "I've had a strong run — [achievement]. The scope is now mostly [maintenance / single product / limited platform work]. I'm looking for **multi-team platform impact** and a domain I care about. Autodesk checks both boxes."

---

## "Why Now?"

> "Cloud platform investments are accelerating — APS, web viewers, collaboration. Principals who establish architecture now will define the next decade of how these products are built. I'd rather join during the transition than after patterns are set in stone."

---

## Questions They Might Ask Back

### "What do you know about our challenges?"

**Answer:**
> "Balancing legacy desktop performance expectations with web latency. Handling large design files in the browser via translation/viewer pipelines. Multi-tenant permissions across projects and orgs. Operating global services with data residency. These are hard, interesting problems — not CRUD apps."

### "What would you do in your first 90 days?"

**Answer:**
```
Days 1–30:   Listen — codebase, on-call, team pain, customer tickets, architecture docs
Days 31–60:  Ship one visible improvement + one RFC on highest-friction platform gap
Days 61–90:  Align 2+ squads on a shared pattern (auth, errors, design tokens); mentor
```
> "I wouldn't reorganize architecture in month one — credibility comes from understanding first."

---

## Authenticity Checklist

- [ ] At least one **true** personal connection to design/build/manufacturing
- [ ] Name **specific** Autodesk products or APS APIs you looked up
- [ ] Tie to **your** resume projects (viewer, large files, collaboration, OAuth)
- [ ] Sound interested in **mission**, not just comp or title
- [ ] Prepared for "what concerns you about joining?"

**Honest concern example:**
> "I've heard the interview process can be long — I'm committed through the loop. I've also read some teams skew maintenance-heavy; I'd want to understand this team's roadmap in the HM conversation."

---

## Avoid These Answers

| Weak | Stronger |
|------|----------|
| "Great work-life balance" (Glassdoor quote — sounds unmotivated) | "Mission + technical challenge + platform scope" |
| "I use AutoCAD" (if you don't) | "I've reviewed APS Viewer React samples" |
| "Principal title for resume" | "Org-level leverage during cloud transition" |
| Generic "FAANG for design" | Specific APS + collaboration + your stack |
